## 1. 구축 전 요구사항 분석

### 현재 PC 사양 확인

사진만으로는 GPU가 확정되지 않습니다. PowerShell에서 확인하십시오.

```powershell
Get-CimInstance Win32_Processor |
  Select-Object Name, NumberOfCores, NumberOfLogicalProcessors

Get-CimInstance Win32_ComputerSystem |
  Select-Object @{Name="RAM_GB";Expression={[math]::Round($_.TotalPhysicalMemory/1GB,1)}}

Get-CimInstance Win32_VideoController |
  Select-Object Name, VideoProcessor, AdapterRAM, DriverVersion

Get-Volume |
  Select-Object DriveLetter, FileSystem, SizeRemaining, Size

wsl --status
```

GPU가 나오지 않거나 VRAM이 1~2GB 수준이면 CPU-only 구성을 기준으로 잡는 것이 안전합니다.

### Windows 고려사항

- Windows 11은 파일럿과 공용 PC 단독 사용에 편리합니다.
- Docker Desktop은 WSL2 백엔드를 권장합니다.
- Docker Desktop 사용에는 가상화가 BIOS에서 활성화되어야 합니다.
- GPU를 Docker에서 사용하려면 WSL2, GPU 드라이버, 컨테이너 런타임 구성이 추가로 필요합니다.
- Ollama Windows 버전은 기본적으로 `127.0.0.1:11434`에 API를 열고 백그라운드에서 실행됩니다. [Ollama Windows 공식 문서](https://docs.ollama.com/windows)
- Docker Desktop은 기업 규모에 따라 유료 구독이 필요할 수 있습니다. 공식 문서상 250명 초과 직원 또는 연매출 1,000만 달러 초과 조직은 상업용 유료 조건을 확인해야 합니다. [Docker Desktop 공식 문서](https://docs.docker.com/desktop/setup/install/windows-install/)

### Linux 고려사항

다중 사용자 서버에는 Linux가 더 적합합니다.

- Ubuntu LTS 또는 사내 표준 Linux 사용
- systemd로 Ollama 자동 시작
- Docker Engine 및 NVIDIA Container Toolkit 사용
- UFW/nftables 방화벽
- 서비스 계정 분리
- `/srv/models`, `/srv/open-webui`, `/srv/qdrant` 등 데이터 경로 표준화
- UPS, 디스크 RAID 또는 정기 백업
- SSH 접근을 관리자망으로 제한

Qwen3는 한국어를 포함한 100개 이상의 언어를 지원하고, 8B 모델은 8.2B 파라미터와 기본 32K 컨텍스트를 제공합니다. [Qwen3-8B 모델 카드](https://huggingface.co/Qwen/Qwen3-8B) [Qwen3-14B 모델 카드](https://huggingface.co/Qwen/Qwen3-14B)

Gemma 3 12B는 140개 이상의 언어, 128K 컨텍스트, 질의응답·요약·이미지 입력을 지원하지만 Google의 별도 Gemma 사용 조건을 확인해야 합니다. [Gemma 3 모델 카드](https://huggingface.co/google/gemma-3-12b-it)

GPT-OSS 20B는 Apache-2.0이며 MXFP4 기준 16GB 메모리 안에서 실행 가능하다고 모델 카드에 안내되어 있습니다. [GPT-OSS 20B 모델 카드](https://huggingface.co/openai/gpt-oss-20b)

EXAONE 4.0은 한국어·영어·스페인어를 지원하지만 모델 카드에 `EXAONE AI Model License Agreement 1.2 - NC`가 표시됩니다. 회사의 영리 업무에 사용하기 전 법무·라이선스 검토가 필요합니다. [EXAONE 4.0 모델 카드](https://huggingface.co/OpenLLM-Korea/EXAONE-4.0-32B)

### 추천 모델 3개

1. `Qwen3 8B Q4`  
   현재 PC에서 가장 현실적인 기본 모델

2. `Qwen3 14B Q4/Q5`  
   64GB RAM 또는 12~16GB VRAM 이상 환경에서 문서 품질 개선

3. `GPT-OSS 20B`  
   Apache-2.0 기반의 추론·초안 작성용 후보

한국어 최고 품질을 별도로 평가하려면 EXAONE 4.0을 테스트할 수 있지만, 상업적 사내 업무 사용은 라이선스 확인 전 운영 모델로 채택하지 않는 것이 안전합니다.

## 5. 실제 설치 절차

### 선정 구성

현재 PC에서 먼저 검증할 구성은 다음과 같습니다.

> Docker Desktop + Open WebUI의 Ollama 포함 이미지 + Qwen3 8B

Open WebUI 공식 문서에도 Ollama 포함 CPU-only 컨테이너 구성이 안내되어 있습니다. 운영 환경에서는 `main`, `latest`와 같은 rolling tag 대신 특정 버전 태그를 고정해야 합니다. [Open WebUI 설치 문서](https://docs.openwebui.com/getting-started/quick-start/)

### 1단계: WSL2 확인

관리자 PowerShell에서 실행합니다.

```powershell
wsl --status
```

설치되지 않았다면 다음을 실행하고 재부팅합니다.

```powershell
wsl --install
```

Docker Desktop 설치 후에는 WSL2 backend를 선택합니다.

### 2단계: Docker Desktop 설치

공식 사이트에서 Windows용 Docker Desktop을 설치합니다.

설치 시:

- Use WSL 2 instead of Hyper-V 선택
- Docker Desktop 자동 시작 활성화
- Windows Defender 방화벽 허용은 사내 정책에 맞게 진행
- Docker Hub/GHCR 외부 다운로드는 초기 설치 시에만 허용

### 3단계: 보안 키 생성

PowerShell에서 실행합니다.

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$secret = -join ($bytes | ForEach-Object { $_.ToString("x2") })
$rng.Dispose()

$secret
```

출력된 키는 저장해 두십시오. Open WebUI 컨테이너를 재생성할 때 동일한 키가 필요합니다.

### 4단계: Open WebUI와 Ollama 실행

파일럿용 명령입니다.

```powershell
$webuiImage = "ghcr.io/open-webui/open-webui:ollama"

docker run -d `
  --name open-webui `
  --restart unless-stopped `
  -p 3000:8080 `
  -v ollama:/root/.ollama `
  -v open-webui:/app/backend/data `
  -e "WEBUI_SECRET_KEY=$secret" `
  -e "OLLAMA_NO_CLOUD=1" `
  -e "OLLAMA_NUM_PARALLEL=1" `
  -e "OLLAMA_CONTEXT_LENGTH=8192" `
  -e "OLLAMA_MAX_LOADED_MODELS=1" `
  -e "OLLAMA_MAX_QUEUE=16" `
  -e "OFFLINE_MODE=true" `
  -e "HF_HUB_OFFLINE=1" `
  -e "RAG_EMBEDDING_MODEL_AUTO_UPDATE=false" `
  -e "RAG_RERANKING_MODEL_AUTO_UPDATE=false" `
  -e "WHISPER_MODEL_AUTO_UPDATE=false" `
  $webuiImage
```

`OFFLINE_MODE`는 Open WebUI의 자동 업데이트와 모델 다운로드를 제한하지만, 외부 API 호출을 방화벽 수준에서 차단하는 기능은 아닙니다. 따라서 실제 보안은 반드시 방화벽 또는 망분리로 보완해야 합니다. [Open WebUI 오프라인 운영 문서](https://docs.openwebui.com/tutorials/maintenance/offline-mode/)

운영 환경에서는 다음처럼 특정 안정 버전을 사용하십시오.

```powershell
$webuiImage = "ghcr.io/open-webui/open-webui:vX.Y.Z-ollama"
```

`vX.Y.Z`는 설치 시점의 공식 Releases 페이지에서 확인하십시오.

### 5단계: 모델 다운로드

인터넷이 허용된 준비 시간에 실행합니다.

```powershell
docker exec -it open-webui ollama pull qwen3:8b
```

설치된 모델 확인:

```powershell
docker exec -it open-webui ollama list
```

모델 상세 확인:

```powershell
docker exec -it open-webui ollama show qwen3:8b
```

추가 후보 모델:

```powershell
docker exec -it open-webui ollama pull qwen3:14b
docker exec -it open-webui ollama pull gpt-oss:20b
```

모델 태그는 변경될 수 있으므로 Ollama 공식 모델 라이브러리에서 실제 태그를 확인하십시오.

### 6단계: CLI 테스트

```powershell
docker exec -it open-webui ollama run qwen3:8b "다음 문장을 세 줄로 요약해 주세요. 사내 문서 검토를 위한 테스트 문장입니다."
```

Qwen3의 일반 문서 작업은 생각 모드를 끄는 `/no_think` 옵션으로 더 빠르게 사용할 수 있습니다.

```powershell
docker exec -it open-webui ollama run qwen3:8b "다음 문서를 핵심 내용 5개로 요약해 주세요. /no_think"
```

### 7단계: 웹 UI 접속

같은 PC에서 다음 주소를 엽니다.

```text
http://127.0.0.1:3000
```

처음 접속하면 관리자 계정을 생성합니다.

관리자 계정 생성 후:

1. 관리자 메뉴 접속
2. Authentication 또는 사용자 설정 이동
3. 신규 가입 허용 중지
4. 필요한 사용자만 별도 계정 생성
5. 관리자 계정은 일반 사용자로 사용하지 않음

Open WebUI는 첫 계정 생성 이후 관리자 패널에서 신규 가입을 제한할 수 있습니다. [Open WebUI Quick Start](https://docs.openwebui.com/getting-started/quick-start/)

### 8단계: 자동 실행

Docker 컨테이너는 다음 옵션으로 자동 재시작됩니다.

```text
--restart unless-stopped
```

Docker Desktop에서도 다음을 활성화하십시오.

```text
Settings → General → Start Docker Desktop when you sign in
```

### 9단계: Windows 방화벽

실제 사내 대역으로 수정하십시오.

```powershell
$corpCidrs = @("10.20.30.0/24")

New-NetFirewallRule `
  -DisplayName "Internal Local LLM Web UI" `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 3000 `
  -Profile Domain `
  -RemoteAddress $corpCidrs

New-NetFirewallRule `
  -DisplayName "Block Direct Ollama API" `
  -Direction Inbound `
  -Action Block `
  -Protocol TCP `
  -LocalPort 11434 `
  -Profile Any
```

Ollama API는 인증이 기본 제공되지 않으므로 사내 사용자에게 직접 공개하면 안 됩니다. [Ollama API 인증 문서](https://github.com/ollama/ollama/blob/main/docs/api/authentication.mdx)

### 10단계: 다른 PC에서 접속

서버 PC에서 IP를 확인합니다.

```powershell
ipconfig
```

예를 들어 서버 IP가 `10.20.30.15`라면 다른 PC 브라우저에서 접속합니다.

```text
http://10.20.30.15:3000
```

다른 PC에서 포트 테스트:

```powershell
Test-NetConnection 10.20.30.15 -Port 3000
```

다음 주소는 사용자에게 제공하지 않습니다.

```text
http://10.20.30.15:11434
```

### 11단계: 정상 동작 확인

```powershell
docker ps
docker logs --since 30m open-webui
docker stats open-webui
docker exec -it open-webui ollama ps
```

정상 기준:

- 컨테이너 상태가 `Up`
- Open WebUI 로그인 가능
- Qwen3 모델 표시
- 질문에 응답
- `ollama ps`에서 모델이 CPU에 로드됨
- 외부 모델이나 외부 API 연결이 설정되어 있지 않음
- 방화벽에서 3000만 사내망에 허용됨

### 외부 전송 방지

다음 세 가지를 모두 적용해야 합니다.

1. Ollama Cloud 비활성화
2. Open WebUI에서 외부 Provider 미등록
3. 네트워크 방화벽에서 인터넷 outbound 차단

`OFFLINE_MODE`만으로 모든 외부 연결이 차단되는 것은 아닙니다. Open WebUI 공식 문서도 외부 API, OAuth, 웹 검색 등은 네트워크가 허용되면 연결될 수 있다고 설명합니다. [Open WebUI 오프라인 문서](https://docs.openwebui.com/tutorials/maintenance/offline-mode/)

### 업데이트 방식

운영 중인 시스템에서 즉시 자동 업데이트하지 마십시오.

권장 절차:

```text
인터넷 연결 허용
    ↓
공식 이미지·모델 다운로드
    ↓

    ↓

    ↓

    ↓
운영 반영
    ↓

```

Open WebUI는 운영 시 rolling tag보다 특정 버전 태그를 고정하도록 권장합니다. [Open WebUI 버전 태그 안내](https://docs.openwebui.com/getting-started/quick-start/)

### 악성 프롬프트와 파일

특히 RAG 구축 후 다음 공격을 주의해야 합니다.

- 문서 안에 “이전 지시를 무시하라”는 프롬프트 삽입
- 악성 매크로 포함 Office 파일
- 과도하게 큰 PDF를 통한 자원 고갈
- 비밀번호·API 키가 포함된 문서 업로드
- 문서 내용에 포함된 외부 URL 자동 실행
- 모델에게 파일 삭제·명령 실행을 허용하는 플러그인

대응 원칙:

- 검색 문서는 지시문이 아니라 데이터로 처리
- 검색 문서 내 지시는 실행하지 않도록 시스템 프롬프트에 명시
- 웹 검색·터미널·코드 실행 기능은 기본 차단
- PDF·Office 파일은 백신 및 샌드박스 검사
- 업로드 크기·페이지 수·문서 수 제한
- 모델이 근거를 찾지 못하면 “확인할 수 없음”으로 답변

### 필요한 구성요소

| 접근권한 | 사용자·부서·문서등급 메타데이터 필터 |

### 데이터 흐름

```text
[PDF/Word/Excel/매뉴얼]
          │
          ▼
[악성 파일 검사 / OCR / 텍스트 추출]
          │
          ▼
[문서 정규화 및 청킹]
          │
          ▼
[임베딩 모델]
          │
          ▼
[Qdrant 또는 pgvector]
          │
          ▼
[사용자 질문]
          │
          ▼
[검색 + 권한 필터 + 재순위화]
          │
          ▼
[관련 문서 조각과 출처를 프롬프트에 삽입]
          │
          ▼
[로컬 LLM]
          │
          ▼
[근거 페이지가 포함된 답변]
```

### 초기 청킹 권장값

- 일반 문서: 400~800 토큰
- 청크 중복: 50~100 토큰
- 문서 제목·장·페이지·작성부서·보안등급을 메타데이터로 저장
- 표는 행·열 관계가 유지되도록 별도 처리
- 스캔 문서는 OCR 신뢰도도 기록

### TypeSafe 적용 방식

이번 요청에는 TypeSafe의 “route → rank → verify” 설계 패턴을 적용했습니다.

- `Choice`: 요약, 번역, 질의응답, 문서검색 등 작업 유형 분류
- `Score`: 검색된 문서 조각의 질문 관련도 평가
- `Noul`: 해당 문서에 답변 근거가 존재하는지 판단
- 검증 실패 시 답변 생성 대신 사용자에게 추가 문서 요청
- 근거 없는 답변은 자동으로 “확인 필요” 처리

## 기존 Docker 명령 수정

앞서 제공한 Open WebUI + Ollama 컨테이너 명령에는 GPU 옵션을 추가해야 합니다.

기존 컨테이너를 유지하면서 재생성하려면 먼저 컨테이너만 제거합니다. Docker 볼륨은 삭제하지 마십시오.

```powershell
docker rm -f open-webui
```

그 다음 `--gpus=all`을 추가하여 실행합니다.

```powershell
docker run -d `
  --name open-webui `
  --restart unless-stopped `
  --gpus=all `
  -p 3000:8080 `
  -v ollama:/root/.ollama `
  -v open-webui:/app/backend/data `
  -e "WEBUI_SECRET_KEY=$secret" `
  -e "OLLAMA_NO_CLOUD=1" `
  -e "OLLAMA_NUM_PARALLEL=1" `
  -e "OLLAMA_CONTEXT_LENGTH=8192" `
  -e "OLLAMA_MAX_LOADED_MODELS=1" `
  -e "OLLAMA_MAX_QUEUE=16" `
  -e "OFFLINE_MODE=true" `
  -e "HF_HUB_OFFLINE=1" `
  -e "RAG_EMBEDDING_MODEL_AUTO_UPDATE=false" `
  -e "RAG_RERANKING_MODEL_AUTO_UPDATE=false" `
  -e "WHISPER_MODEL_AUTO_UPDATE=false" `
  ghcr.io/open-webui/open-webui:ollama
```

Open WebUI 공식 문서도 Ollama 포함 이미지에 `--gpus=all`을 사용하는 GPU 구성을 안내합니다. [Open WebUI GPU 구성](https://docs.openwebui.com/getting-started/quick-start/)

모델을 다운로드합니다.

```powershell
docker exec -it open-webui ollama pull qwen3:8b
docker exec -it open-webui ollama pull qwen3:14b
```

GPU 사용 여부를 확인합니다.

```powershell
docker exec -it open-webui ollama run qwen3:14b "다음 문서를 핵심 내용 5개로 요약해 주세요. /no_think"
```

```powershell
docker exec -it open-webui ollama ps
```

정상이라면 `PROCESSOR` 또는 유사 항목에 GPU 사용률이 표시됩니다. `100% CPU`로 표시되면 Docker Desktop의 WSL2 GPU 연동이나 NVIDIA 드라이버를 확인해야 합니다.
